# Product vision

**Status:** Agreed strategic requirement, 2026-11-17. **Confidence:** high; supplied explicitly by the user in this conversation.

## Direction

AI-Worker is intended to become a broadly capable autonomous engineering and work agent, not merely a GitHub bot. GitHub is the first proving ground. Plausible future integrations include GitLab, Bitbucket, Jira, paid task marketplaces, and authorized private repositories; these are strategic possibilities, not implemented capabilities or committed delivery dates.

The end-to-end engineering capability should mature across:

- Issue and task comprehension.
- Repository intelligence.
- Dependency-aware multi-file planning.
- Safe patch generation.
- Real, project-aware testing.
- Independent review.
- Bounded repair loops.
- Reproducible handoff.
- Sandboxed execution.
- Durable state, recovery, and concurrency.

## Commercial evidence rules

- Commercial objectives must be measured, not asserted.
- Do not claim revenue, profitability, successful customer validation, or market fit without direct evidence.
- Listed rewards, estimated rewards, accepted tasks, and submitted work are not actual income. Only recorded funds actually received count as income; fees and hours should be tracked separately.

## Current gap

The current product documents describe a local-first, GitHub-centered development pipeline and a separate paid-opportunity scout. This is a narrower implemented starting point than the long-term vision. Treat every capability as current only after confirming it in the checked-out source and tests.
